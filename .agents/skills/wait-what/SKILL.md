# Wait, What?

Pause the workflow. The previous answer did not land; explain it again, rather than continuing the task.

- Start with the problem and where we are in the discussion.
- Explain what you propose, why it helps, and what would change for this project.
- Use short sentences and existing project names. Define necessary technical terms and use one concrete example when helpful.
- Separate established facts from assumptions or recommendations.
- End with the decision or question that needs the user's attention, if any.

Do not require a glossary, create documents, or make implementation changes. Make the explanation clearer, not merely longer.
